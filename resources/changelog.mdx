LlamaLibrary is actively maintained and updated alongside Final Fantasy XIV patches and RebornBuddy releases. Because LlamaLibrary reads game memory directly, it must be updated whenever the game changes the internal structures it depends on. Staying current is not optional — an outdated installation can cause crashes, broken behavior, or silent failures in any botbase or plugin that depends on the library.

## Week of August 3, 2026

### Updates

- **Actionable Duty Finder queue errors.** `DutyManager.CanQueue` now decodes the game's native queue-restriction flags into meaningful reasons (for example, "equipped average item level below the duty requirement" when restriction flag `16` is set) instead of the previous sequential 1/2/3 codes. Multiple restrictions are reported together as combinable flags, the raw value is preserved, and unknown future bits are surfaced for diagnostics so scripts can tell users exactly why a duty won't queue.
- **Stability pass on recent offsets.** Recently added memory reads have been moved from hardcoded, wrapper-local layouts to signature-scanned patterns centralized in the offset system, covering the `ShopExchangeCoin` MGP exchange nodes, `GcArmyExpedition` squadron state, `Buddy` and `CompanionInfo` chocobo fields, and the `AgentContentsInfo` estate timer arrays. The Buddy pattern has a dedicated Taiwan override for the structurally different TC constructor. Expect fewer breakages on these surfaces after future client updates. See the [remote window reference](/reference/remote-windows) and [helpers overview](/reference/helpers-overview).
- **Hardened MGP exchange offsets.** The `ShopExchangeCoin` window's call-pattern anchors have been replaced with operand-masked signatures that survive minor client shifts, and the underlying agent is now discovered through a cacheable vtable anchor instead of rescanning at every RebornBuddy startup. The offset cache version has been bumped so cached values refresh on first launch. See the [remote window reference](/reference/remote-windows).

### Bug fixes

- **Estate offset startup errors resolved.** `EstateStatusArray` and `EstateDeadlineArray` are fixed structure-layout constants rather than signatures. Offset discovery now excludes literal constant fields from cache restoration and pattern resolution, eliminating the `No attribute found`, `Not Found`, and `Cannot set a constant field` errors some users saw at startup after the initial estate demolition helper landed.
- **Minion `BaseId` reads restored.** `GameObject.BaseId` for minions was reading the wrong location after the game's post-GimmickId layout change. The read has been re-anchored to a semantic signature that resolves the current layout, so minion identification works again.

## Week of July 27, 2026

### New features

- **Estate auto-demolition status.** A new `EstateDemolitionStatus` helper exposes the estate timer data cached by the Contents Info / Timers agent, so scripts can detect endangered houses without opening or interacting with the Timers window. The one-minute cached snapshot reports per-estate state (scheduled, not scheduled, unknown) and a validated demolition deadline for the free company estate, private estate, and up to two shared estates the current character is a tenant on. `VerifyCancellationAsync(estateType)` polls refreshed client data to confirm a timer was actually cleared instead of assuming success from zoning. Release, China, and Taiwan clients are supported. See the [helpers overview](/reference/helpers-overview).
- **MGP exchange window.** A new `ShopExchangeCoin` remote window drives the gil-to-MGP exchange UI end to end. `SetAmount(int)` sets the requested MGP amount and refreshes the required gil, `Proceed(int)` completes the exchange, and `Cancel()` dismisses the window. Amounts are clamped to the game's supported range of 1–500. See the [remote window reference](/reference/remote-windows).
- **Quest-ID-only access to protected profiles.** A new `ProtectedQuestProfileLibrary`, built on a `ProtectedRepositoryResourceClient`, lets plugins request a protected OrderBot quest profile by quest ID alone — the library resolves the catalog path (with legacy fallback), fetches the file through the plugin's own authenticated provider, validates size and SHA-256, and returns the XML or the inner Order XML. Content is cached per credential and per catalog SHA, and the credential can be rotated without leaking cached bytes. Callers never see repository credentials or layout. See the [helpers overview](/reference/helpers-overview).

### Bug fixes

- **Inn room retirement now works in every client language.** `NavigationHelper.GoToInnRoom` no longer relies on a hard-coded English "Retire to an inn room" line and instead selects the localized entry (English, Japanese, French, German, Simplified and Traditional Chinese), so inn workflows are reliable on non-English clients.
- **Squadron deployment no longer stalls after Edit Squad.** `GcArmyExpedition.Deploy` no longer refuses to fire when the addon's advisory `CanDeploy` flag is momentarily false after returning from Edit Squadron — the confirmation window is now treated as the authoritative validation, matching what the visible Deploy button already accepted.
- **Beast tribe reputation reads updated for global patch 7.5.** `BeastTribeHelper.GetBeastTribes` now reads the current `BeastReputation` offset (`0xCE8`) on the global client and keeps the previous `0xCA8` for Taiwan, and the underlying `BeastTribeExd` currency field was widened to `uint` to match the new client layout. Reputation and rank reads no longer return garbage after 7.5.
- **Out on a Limb director aligned across regions.** The `MiniGameNumberArrayIndex` used by `OutOnALimbDirector` is now `104` on both global and Taiwan clients after the TC 7.2 update brought the layouts in sync.
- **Triple Triad "NPC beaten" lookup restored.** The `UIState.TripleTriadNpcBeaten` offset pattern was updated to match the current client, so `TripleTriadNpcBeaten(residentId)` (and any callers that skip already-beaten opponents) returns correct results again.
- **Materia read patterns restored.** The `BagSlotMateriaType` and `BagSlotMateriaLevel` offsets were reverted from hard-coded constants back to signature-scanned patterns, so materia reads keep working across future client shifts instead of silently reading the wrong bytes.
- **Taiwan client patterns updated for patch 7.2.** A broad refresh of TC offset patterns across the Inventory Manager, Grand Company turn-in, Desynth lock, Teleport helper, UI input, Housing Signboard, Achievements, Retainer Ventures, Satisfaction supplies, Hunts, Item Finder, Looking For Group, Race Chocobo Manager, Request helper, Shop Proxy, Free Company info, and more brings the Taiwan client back in sync with the global signature set.
- **`Lisbeth.IsProductKeyValid` awaits directly.** The wrapper no longer double-wraps the call through `Coroutine.ExternalTask` since Lisbeth handles that internally, avoiding an unnecessary coroutine hop on every product-key validity check.

## Staying up to date

You have two options for keeping LlamaLibrary current:

**updateBuddy (recommended)**

Install the [updateBuddy](https://loader.updatebuddy.net/UpdateBuddy.zip) plugin into your `Plugins\updateBuddy` folder. Each time RebornBuddy starts, updateBuddy checks the LlamaLibrary GitHub repository for new commits and applies any updates automatically. You do not need to monitor releases or pull changes manually.

**Manual updates**

If you prefer not to use updateBuddy, you can update LlamaLibrary yourself:

1. Download or pull the latest from [https://github.com/nt153133/__LlamaLibrary](https://github.com/nt153133/__LlamaLibrary).
2. Replace the contents of your `QuestBehaviors\__LlamaLibrary` folder with the new files.
3. Restart RebornBuddy.

This approach requires you to check for updates yourself, particularly after every FFXIV patch.

## Why updates matter

FFXIV patches routinely change game memory layouts, internal function signatures, and UI structures. LlamaLibrary's offset system reads these memory locations directly to expose game data and trigger game actions. When a patch ships, previously valid offsets may point to wrong locations or no longer exist at all.

Running an outdated version of LlamaLibrary after a game patch can cause:

- RebornBuddy crashes on startup during offset initialization
- Incorrect or missing data returned from game memory reads
- Broken interactions with game UI windows and agents
- Navigation and retainer automation failures

Updating LlamaLibrary immediately after an FFXIV patch is the single most effective step you can take to prevent these problems.

<Warning>
  Always update LlamaLibrary immediately after every FFXIV patch and before reporting any bug. Many issues that appear to be botbase bugs are caused by stale offsets in an outdated LlamaLibrary installation. Running the latest version rules out the most common cause of breakage.
</Warning>

## What changes between versions

Updates to LlamaLibrary fall into several recurring categories:

**Offset updates after FFXIV patches**
The most common type of update. When a game patch changes internal memory structures, offsets throughout LlamaLibrary are recalibrated to match the new layout.

**New remote window wrappers**
When FFXIV adds or changes game UI windows and agents, LlamaLibrary adds or updates the corresponding remote window and agent wrapper classes so botbases can interact with them.

**New helper functions for game content**
As new game content ships — new duties, crafting recipes, retainer ventures, Grand Company items — LlamaLibrary gains helper functions and resource data to support automation of that content.

**Bug fixes for retainer, navigation, and crafting helpers**
Targeted fixes for specific failure modes in the retainer automation, navigation provider integration, and crafting helper subsystems.

**New template class features**
Improvements to `TemplateBotBase`, `TemplatePlugin`, and related scaffolding — such as new lifecycle hooks, updated logging behavior, or convenience properties.
